# Бизнес-логика системы ИСП (Информационная Система Подготовки)

## Общее описание

ИСП — многопользовательская СДО (система дистанционного обучения) для учебных центров (УЦ) и организаций-клиентов в сфере промышленной и энергетической безопасности. Система позволяет:
- Управлять обучением сотрудников по направлениям госстандартов
- Принимать онлайн-заявки от организаций через STP-портал
- Выдавать удостоверения ДПО после прохождения курсов
- Оформлять протоколы проверки знаний по электробезопасности

---

## 1. Тенанты и организации

### Типы тенантов

**Учебный центр (`training_center`)**
- Основная операционная единица системы
- Может иметь несколько организаций-клиентов
- Имеет лицензию на образовательную деятельность (`licenseNo`, `licenseDate`)
- Может выдавать удостоверения ДПО
- Видит все табы и отчёты

**Организация-клиент (`organization`)**
- Предприятие, которое отправляет сотрудников на обучение в УЦ
- Не может самостоятельно выдавать удостоверения
- Видит ограниченный набор функций (без таба «Удостоверения», без реестра сертификатов)

### Статусы тенанта
| Статус | Значение |
|---|---|
| `active` | Полный доступ |
| `trial` | Пробный период, ограниченное время |
| `suspended` | Доступ приостановлен |

### Подписки
Каждый тенант имеет баланс подписок по направлениям:
- `total` — выделено слотов обучения
- `used` — использовано
- Свободно = `total − used`

При назначении курса сотруднику — `used` увеличивается на 1.

## 2. Направления обучения и курсы

### Направления (`SubscriptionType`)
| ID | Название | Тип подписки | Кол-во курсов |
|---|---|---|---|
| 1 | Промышленная безопасность | `industrial_safety` | 10 |
| 2 | Энергобезопасность | `energy_safety` | 4 |
| 3 | Охрана труда | `labor_protection` | 5 |
| 4 | Подготовка экспертов ПБ | `expert_pb` | 2 |
| 5 | Подготовка экспертов ГТС | `expert_gts` | 2 |
| 6 | Свои курсы | `own_courses` | создаёт УЦ |

### Курсы
Каждый курс имеет:
- Код госстандарта (`А.1.`, `Э.2.`, `Б.1.1.` и т.д.)
- Объём часов (40, 72, 120 ч)
- Признак наличия теста (`hasTest`)
- Признак доступности ДПО-удостоверения (`dpoAvailable`)

### Собственные курсы УЦ
УЦ может создавать и публиковать собственные курсы.

**Жизненный цикл:**
```
draft → pending_approval → approved
                        ↘ rejected (с причиной) → [переработка] → pending_approval
```

Параметры: кол-во вопросов теста, проходной балл (%), лимит времени (мин), режимы теста (`adaptive`, `section`, `final`), материалы и НТД.

## 3. Пользователи и обучение

### Слушатель (User)
- Привязан к группе и организации через `clientOrganizationId`
- Имеет список назначений курсов (`assignments`)

### Жизненный цикл назначения курса (CourseAssignment)
```
pending → active → completed → certified
```

| Статус | Значение | Поля |
|---|---|---|
| `pending` | Назначен, не активирован | `assignedAt` |
| `active` | Проходит курс | `activatedAt`, `progress` (0–100%) |
| `completed` | Завершил, сдал тест | `completedAt`, `testScore`, `testPassedAt` |
| `certified` | Выдано удостоверение | — (обновляется в Certificates) |

### Операции с назначениями
| Операция | Действие |
|---|---|
| `addUser()` | Создаёт пользователя, все курсы — `pending` |
| `toggleCourse()` | Включает/выключает курс в списке |
| `activateCourse()` | `pending` → `active`, фиксирует дату начала |
| `issueCertificate()` | `completed` → `certified` |
| `addCoursesToGroup()` | Добавляет курсы всем в группе |
| `addCoursesToUser()` | Добавляет курсы конкретному пользователю |

## 4. STP-заявки (STP Индекс Безопасности)

### Что это
STP — внешний портал, через который организации подают онлайн-заявки на обучение. Заявки поступают в панель управления УЦ.

### Жизненный цикл заявки
```
new → in_progress → accepted (создаётся группа)
                 ↘ rejected
```

| Статус | Что означает | Действия |
|---|---|---|
| `new` | Новая, не рассмотрена | «Принять в работу» |
| `in_progress` | Взята в работу | «Принять в работу» |
| `accepted` | Принята, группа создана | Только просмотр |
| `rejected` | Отклонена | Только просмотр |

### Принятие заявки: что происходит
1. Пользователь нажимает «Принять в работу» и вводит/подтверждает имя группы
2. Создаётся новая группа:
   - Статус `forming`
   - Привязана к организации-отправителю (ИНН, название)
   - `fromStpRequestId` — ссылка на заявку-источник
   - Курсы определяются из `courseDirectionId` заявки
3. Заявка переходит в `accepted`, фиксируется `acceptedAt` и `createdGroupId`

### Автогенерация имени группы
```
Шаблон: {первое слово направления}-{год}/{порядковый номер}
Пример: Промышленная-2026/03
        Энергобезопасность-2026/05
        ОБУ-2026/07 (если направление не определено)
```

### Поиск по заявкам
Поиск ведётся по: названию организации, имени курса, внешнему ID (STP-2024-0041), ФИО участников.

## 5. Удостоверения ДПО

### Условия выдачи
- Курс завершён (`status: "completed"`)
- Тест пройден (`testScore` > 0, `testPassedAt` заполнен)
- `dpoRequired: true` в назначении (или `dpoAvailable: true` у курса)
- Тенант — `training_center` (организации не выдают)

### Жизненный цикл удостоверения
```
[тест пройден] → ready → issued
```

| Статус | Значение |
|---|---|
| `ready` | Тест сдан, удостоверение готово к оформлению |
| `issued` | Выдано: есть номер (`ДПО-2024-001`), дата, подпись |

### Оформление выдачи
- Администратор вводит номер удостоверения и ФИО выдавшего
- Можно выбирать несколько удостоверений и выдавать массово
- В реестре фильтрация по организации слушателя

## 6. Проверка знаний по электробезопасности (ЭБ)

Реализована по **Приказу Минэнерго РФ № 796 (ред. 2024)**.

### Кто попадает в очередь на проверку
Сотрудник автоматически попадает в **Лист ожидания** если:
- Завершил курс из направления «Энергобезопасность» (courseId: 201–204)
- Успешно сдал тест (`testScore > 0`, статус `completed` или `certified`)
- Не имеет утверждённого протокола проверки

Группировка листа ожидания — по организации (`clientOrganizationId`).

### Статусы в листе ожидания
| Статус | Условие |
|---|---|
| `waiting` | Нет ни одного протокола с этим сотрудником |
| `in_draft` | Включён в черновик протокола |
| `checked` | Есть утверждённый протокол |

### Организации и комиссии
- Каждая организация имеет свои комиссии по проверке знаний
- Комиссия: председатель + минимум 3 члена (по п.58 Приказа)
- Хотя бы один член комиссии должен иметь группу ЭБ IV или V
- Члены комиссии могут быть взяты из базы СДО или добавлены вручную

### Мастер оформления протокола (4 шага)

**Шаг 1 — Комиссия и параметры:**
- Дата проверки
- Причина: `очередная` | `первичная` | `внеочередная` (требует основание)
- Выбор комиссии из активных комиссий организации
- Проверяемые НТД: ПУЭ, ПТБ, ПТЭ, ППБ, Другие (незаполненные будут зачёркнуты в протоколе)

**Шаг 2 — Список проверяемых:**
- Добавление кандидатов из базы СДО
- Указание категории персонала для каждого

**Шаг 3 — Результаты:**
- Оценки по 4 разделам: устройство и эксплуатация, охрана труда, пожарная безопасность, другие правила
- Итоговая оценка рассчитывается автоматически:
  - Любая оценка `неудовл.` → итог `неудовл.`
  - Все `отл.` → итог `отл.`
  - Все `отл.` + `хорошо` → итог `хорошо`
  - Иначе → `удовл.`
- Если хоть у одного `неудовл.` — переход к шагу 4 **заблокирован** (п.63: допуск запрещён, повторная проверка ≤ 1 месяца)

**Шаг 4 — Заключение:**
- Итоговая группа ЭБ (II–V)
- Допуск к работам в ЭУ: до 1000 В / до и свыше 1000 В / не применяется
- Продолжительность дублирования (только для диспетчерского, оперативного, оперативно-ремонтного персонала — п.66)
- Дата следующей проверки:
  - `+365 дней` — для большинства категорий (1 год)
  - `+1095 дней` — для административно-технического персонала без работ в ЭУ (3 года)
- Загрузка КЭП и скана подписи проверяемого

**Финал:**
- «Сохранить черновик» → статус `draft` (можно продолжить позже)
- «Утвердить протокол» → статус `approved` (только чтение, сотрудник переходит в статус `checked`)

### Журнал проверок
- Группировка по организациям
- Фильтры: по статусу (все / утверждённые / черновики)
- Для каждого протокола: раскрытие с результатами всех кандидатов
- Выгрузка в Excel (Приложение №4 к Приказу № 796)

## 7. Статистика

В реальном времени отслеживается:

| Показатель | Источник | Отображение |
|---|---|---|
| `subscriptionsLeft` | Баланс подписок тенанта | Сайдбар |
| `subscriptionsUsed` | Кол-во активных назначений | Сайдбар |
| `inProgress` | Назначения со статусом `active` | Сайдбар |
| `pending` | Назначения со статусом `pending` | Сайдбар |
| `certReadyCount` | Кол-во удостоверений в статусе `ready` | Таб «Удостоверения» (бейдж) |
| `draftCount` (ЭБ) | Протоколы в статусе `draft` | Таб «Журнал проверок» (бейдж) |
| `waitingCount` (ЭБ) | Сотрудники в листе ожидания | Таб «Лист ожидания» (бейдж) |

## 8. Ключевые бизнес-правила (сводка)

| Правило | Источник |
|---|---|
| УЦ может выдавать ДПО-удостоверения, организация — нет | `tenantType` |
| Менеджер не имеет доступа к Настройкам | `role === "manager"` |
| Support видит только `/chat` и `/profile` | `RequireAuth` guard |
| Комиссия ЭБ: минимум председатель + 3 члена, 1 с группой IV/V | п.58 Приказа № 796 |
| При «неудовл.» — утверждение протокола заблокировано | п.63 Приказа № 796 |
| Дублирование обязательно для диспетч./оператив./опер.-ремонт. | п.66 Приказа № 796 |
| Следующая проверка: +1 год (АТ без работ в ЭУ: +3 года) | Приказ № 796 |
| Лист ожидания ЭБ: только курсы `energy_safety` (201–204) | `COURSE_DIRECTIONS` |
| STP-заявка принята = автоматически создаётся группа `forming` | STPPanel logic |
| Балл подписок: `used++` при назначении курса | `useAdminData` |
